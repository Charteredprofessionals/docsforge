## Top 5 Most Urgent Findings

The five most critical findings that pose immediate risk to users:

1. **F-005 + F-006 + F-007 (Critical): The entire GUI and CLI are disconnected from the documented Rust core.** The GUI implements its own DOCX processing with a legacy BLOB-based schema, while the CLI is a hollow stub returning hardcoded responses. The architecture's central promise — "single Rust core, three shells" — is not delivered. Users relying on the CLI for automation would get no actual document processing, and GUI users get no field validation, no RBAC enforcement, and no audit logging.

2. **F-001 + F-002 (Critical): Cross-run and cross-paragraph field matching silently fails.** Any document with formatted text (bold, italic, different fonts) or multi-paragraph fields will have fields that cannot be created. The failure is silent — no error message, the field simply doesn't get tagged. This is the core value proposition of the product and it breaks under realistic conditions.

3. **F-003 + F-014 (Critical): PDF export is non-functional.** The core module returns a corrupt stub PDF. The only working path requires LibreOffice, which contradicts the architecture's "zero dependencies" promise and the documented "clean Windows VM" requirement.

4. **F-008 (Critical): The fidelity gate test is fabricated.** The `fidelity_gate.rs` test that should validate 100% tag fidelity across 50 DOCX fixtures returns hardcoded success without testing anything. No actual fixtures exist. This means the quality gate that was "passed (24/24 tests)" does not include meaningful validation of the core document processing logic.

5. **F-004 + F-016 (Critical): HTML preview sanitization is insecure.** The naive string-replacement sanitizer is trivially bypassable with standard XSS payloads. The React components render this output via `dangerouslySetInnerHTML`, creating a potential code execution vector in the desktop application's webview context.
