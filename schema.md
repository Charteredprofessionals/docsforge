# DocForge — Data Schema Specification (Data Model v3)

> Owner: Data Engineer | Engine: Authr OS SDLC Studio (Phase 1–4 re-approval)
> Status: aligned with `architecture.md` v2 §15 (Data Model v3) and §20 (migration path) —
> **planned (v2.0.0)**
> Scope: DDL specification only — no application source code. Evolves the shipped v4 schema
> (Data Model v2 + template bundles + bug book) into the **Bundle + Matter** document-automation
> domain. All v1/v4 tables are preserved exactly (no column changes); the v2 domain adds the
> tables in §3.18–§3.27. SQLite via `rusqlite` (bundled), WAL mode, metadata-only index.
> Target `PRAGMA user_version = 5`.

---

## 1. Storage Principles

| Principle | Rule | Source |
|---|---|---|
| FS-backed templates, no BLOBs | `templates` and `template_versions` store a filesystem `storage_path` only. Document bytes live under `<app_data>/docforge/templates/<template_id>/v<version>/template.docx`, DPAPI-encrypted at rest on Windows (REQ-019). No BLOB columns anywhere in the index. | REQ-004, AC-004, ADR-003 |
| Bundle documents FS-backed | `bundle_documents` references `templates(id)` and the template's `storage_path`; bundle assets live under `<app_data>/docforge/bundles/<bundle_id>/v<version>/documents/`. Bundle document bytes are never stored in SQLite — the same no-BLOB rule as templates. | REQ-004, REQ-023, ADR-003 |
| Generated output FS-backed | `generated_documents.output_path` is a filesystem path under `<app_data>/docforge/output/<matter_id>/<run_id>/`. Output bytes (DOCX/PDF) never enter the database; paths are canonicalized and containment-checked before read/write. | REQ-034, REQ-018, ADR-003 |
| Integrity hash | Every stored template version keeps a `content_sha256` (hex, 64 chars) computed over the file bytes at save time and re-verified on load, rollback, and export. Matter input snapshots carry `input_snapshot_hash` over the canonicalized value set. | REQ-004, REQ-010, REQ-033 |
| Immutable audit | `generation_log` is append-only: application never exposes UPDATE/DELETE, triggers reject them, FK actions default to RESTRICT so referenced rows cannot be deleted out from under the audit. `generation_runs` and published `bundle_versions` are append-only the same way. | REQ-013, AC-013, REQ-024, REQ-033 |
| Offline-first | All tables are local; nothing is written unless the user opts in (telemetry/cloud surfaces are zero-knowledge). `matters.org_id` is nullable so personal local-first workspaces never require an org row. | REQ-019, REQ-020 |
| SQLite runtime settings | `PRAGMA journal_mode = WAL; PRAGMA foreign_keys = ON; PRAGMA busy_timeout = 5000;` single-writer model per architecture §10. | architecture §10/§15 |

**Identifiers:** every PK is a `TEXT` UUID (v4, generated by the `uuid` crate) unless
noted. **Timestamps:** ISO-8601 UTC `TEXT` via `datetime('now')`. **Booleans:**
`INTEGER` `0|1`. **JSON:** validated `TEXT` documents; the application parses with
`serde_json` and rejects malformed input before write. The single exception to the
no-BLOB rule is the pre-existing `bug_attachments.data_b64` (admin diagnostic
attachments, v4 — preserved as-is, not document content).

### 3.18 `bundle_versions` — immutable Bundle definition snapshots (REQ-023, REQ-024, ADR-010)

**Rationale:** a Bundle Version is the snapshot a Matter binds to and a Generation Run
references. `manifest_json` holds the full documents list + output configuration;
child tables (§3.19–§3.23) hang off `bundle_version_id` so a published definition is
fully reconstructible. **Published rows are immutable:** `UNIQUE (bundle_id, version)`
plus append-only triggers (below) mirror the `generation_log` pattern.

```sql
CREATE TABLE bundle_versions (
  id            TEXT PRIMARY KEY,
  bundle_id     TEXT NOT NULL REFERENCES bundles(id) ON DELETE CASCADE,
  version       INTEGER NOT NULL,
  status        TEXT NOT NULL DEFAULT 'draft'
                CHECK (status IN ('draft','review','published','archived')),
  manifest_json TEXT NOT NULL,          -- documents list + output config snapshot
  created_by    TEXT NOT NULL REFERENCES users(id),
  note          TEXT,                   -- human note, e.g. "add equity annex"
  created_at    TEXT NOT NULL DEFAULT (datetime('now')),
  UNIQUE (bundle_id, version)
);

-- Published Bundle Versions are immutable (REQ-024, ADR-010)
CREATE TRIGGER trg_bundle_versions_published_append_only_update
BEFORE UPDATE ON bundle_versions
FOR EACH ROW
WHEN OLD.status = 'published'
BEGIN
  SELECT RAISE(ABORT, 'published bundle_versions is immutable (REQ-024): UPDATE forbidden');
END;

CREATE TRIGGER trg_bundle_versions_published_append_only_delete
BEFORE DELETE ON bundle_versions
FOR EACH ROW
WHEN OLD.status = 'published'
BEGIN
  SELECT RAISE(ABORT, 'published bundle_versions is immutable (REQ-024): DELETE forbidden');
END;
```

Indexes: `UNIQUE (bundle_id, version)` doubles as the required index on `bundle_id`.

### 3.19 `bundle_documents` — documents owned by a Bundle Version (REQ-023, REQ-036)

**Rationale:** ordered membership of tagged DOCX files inside one Bundle Version.
`template_id` is nullable so rule-driven or not-yet-bound documents can be declared at
draft time; `include_default` + `condition_ref` are the join points for `rules`.

```sql
CREATE TABLE bundle_documents (
  id                 TEXT PRIMARY KEY,
  bundle_version_id  TEXT NOT NULL REFERENCES bundle_versions(id) ON DELETE CASCADE,
  template_id        TEXT REFERENCES templates(id),  -- NULL = rule-driven / not yet bound
  position           INTEGER NOT NULL DEFAULT 0,
  include_default    INTEGER NOT NULL DEFAULT 1 CHECK (include_default IN (0,1)),
  condition_ref      TEXT,                           -- reference to a rules row, nullable
  created_at         TEXT NOT NULL DEFAULT (datetime('now'))
);
```

Indexes: `idx_bundle_documents_version ON bundle_documents(bundle_version_id)`.

### 3.20 `fields` — canonical field schema (REQ-026)

**Rationale:** the Bundle-level shared vocabulary. `field_id` is the stable logical id
(e.g. `company.name`) referenced by mappings, rules, and matter values; `type` is closed
for v2.0.0, but `default_json` / `validation_json` / `format` are generic carriers so
later repeating/structured types (address, person, table, file, signature) extend the
CHECK without column churn.

```sql
CREATE TABLE fields (
  id                 TEXT PRIMARY KEY,
  bundle_version_id  TEXT NOT NULL REFERENCES bundle_versions(id) ON DELETE CASCADE,
  field_id           TEXT NOT NULL,      -- stable logical id, e.g. "company.name"
  label              TEXT NOT NULL,
  description        TEXT,
  type               TEXT NOT NULL CHECK (type IN
                     ('text','multiline_text','number','currency','percentage','date',
                      'datetime','boolean','email','phone','url','select','multiselect')),
  required           INTEGER NOT NULL DEFAULT 0 CHECK (required IN (0,1)),
  default_json       TEXT,               -- typed default value (JSON)
  validation_json    TEXT NOT NULL DEFAULT '{}',   -- min/max/pattern/range per type
  format             TEXT,               -- display format hint
  group_id           TEXT REFERENCES field_groups(id),  -- NULL = ungrouped
  position           INTEGER NOT NULL DEFAULT 0,
  created_at         TEXT NOT NULL DEFAULT (datetime('now')),
  UNIQUE (bundle_version_id, field_id)
);
```

Indexes: `idx_fields_version ON fields(bundle_version_id)`;
`UNIQUE (bundle_version_id, field_id)` doubles as the lookup index by stable id.

### 3.21 `field_groups` — named field grouping (REQ-027)

**Rationale:** drives the Matter form's visual separation (shared vs document-specific).
`bundle_version_id` is nullable so a **global reusable group** can be authored once and
referenced from any version's `fields.group_id`.

```sql
CREATE TABLE field_groups (
  id                 TEXT PRIMARY KEY,
  bundle_version_id  TEXT REFERENCES bundle_versions(id) ON DELETE CASCADE, -- NULL = global reusable
  name               TEXT NOT NULL,      -- e.g. "Company details (shared)"
  description        TEXT,
  position           INTEGER NOT NULL DEFAULT 0,
  created_at         TEXT NOT NULL DEFAULT (datetime('now'))
);
```

Indexes: `idx_field_groups_version ON field_groups(bundle_version_id)`.

### 3.22 `field_mappings` — explicit placeholder → canonical field (REQ-028, ADR-011)

**Rationale:** the **explicit deterministic mapping layer**. A document's literal
`{{placeholder}}` is bound to one canonical field in one Bundle Version — never scattered
string replacement in code. `UNIQUE (bundle_version_id, document_id, placeholder)`
prevents duplicate/ambiguous bindings.

```sql
CREATE TABLE field_mappings (
  id                 TEXT PRIMARY KEY,
  bundle_version_id  TEXT NOT NULL REFERENCES bundle_versions(id) ON DELETE CASCADE,
  document_id        TEXT NOT NULL REFERENCES bundle_documents(id) ON DELETE CASCADE,
  placeholder        TEXT NOT NULL,      -- literal, e.g. {{company_name}}
  canonical_field_id TEXT NOT NULL REFERENCES fields(id),
  created_at         TEXT NOT NULL DEFAULT (datetime('now')),
  UNIQUE (bundle_version_id, document_id, placeholder)
);
```

Indexes: `idx_field_mappings_field ON field_mappings(canonical_field_id)`;
`idx_field_mappings_document ON field_mappings(document_id)`.

### 3.23 `rules` — deterministic conditional documents (REQ-036, REQ-037)

**Rationale:** Bundle-level inclusion conditions over canonical field values only
(safe DSL — no unrestricted scripting). `condition_expr` holds the validated expression
(e.g. `security_type == "equity"`); `operator` / `value_json` / `field_id` are the parsed
atoms kept for preview/explain. `field_id` is deliberately a plain TEXT (deviation D6).

```sql
CREATE TABLE rules (
  id                 TEXT PRIMARY KEY,
  bundle_version_id  TEXT NOT NULL REFERENCES bundle_versions(id) ON DELETE CASCADE,
  document_id        TEXT REFERENCES bundle_documents(id),  -- NULL = bundle-level rule
  field_id           TEXT,               -- referenced canonical field id (see D6)
  operator           TEXT,               -- ==, !=, <, <=, >, >=, &&, ||, !, in
  value_json         TEXT,               -- compared value (typed JSON)
  condition_expr     TEXT NOT NULL,      -- safe expression, e.g. security_type == "equity"
  description        TEXT,               -- human reason for include/exclude
  enabled            INTEGER NOT NULL DEFAULT 1 CHECK (enabled IN (0,1)),
  created_at         TEXT NOT NULL DEFAULT (datetime('now'))
);
```

Indexes: `idx_rules_version ON rules(bundle_version_id)`;
`idx_rules_document ON rules(document_id)`.

### 3.24 `matters` — instance of a Bundle Version (REQ-029, REQ-030)

**Rationale:** a Matter is **always** bound to exactly one immutable Bundle Version
(reproducibility — the binding cannot be silently re-pointed by a later publish).
`org_id` is nullable for local-first personal workspaces. `input_snapshot_json` /
`input_snapshot_hash` capture the canonicalized value set that a generation contract
actually used — deterministic re-execution (REQ-033).

```sql
CREATE TABLE matters (
  id                  TEXT PRIMARY KEY,
  name                TEXT NOT NULL COLLATE NOCASE,
  bundle_id           TEXT NOT NULL REFERENCES bundles(id) ON DELETE CASCADE,
  bundle_version_id   TEXT NOT NULL REFERENCES bundle_versions(id),  -- EXACT version
  org_id              TEXT REFERENCES orgs(id),                      -- NULL = local-first personal
  status              TEXT NOT NULL DEFAULT 'draft'
                      CHECK (status IN ('draft','ready','generating','generated')),
  created_by          TEXT REFERENCES users(id),                     -- NULL allowed for local
  created_at          TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at          TEXT NOT NULL DEFAULT (datetime('now')),
  input_snapshot_json TEXT,                   -- canonicalized input at last save/generation
  input_snapshot_hash TEXT,                   -- SHA-256 of canonicalized matter data
  CHECK (input_snapshot_hash IS NULL OR length(input_snapshot_hash) = 64)
);
```

Indexes: `idx_matters_bundle_version ON matters(bundle_version_id)`;
`idx_matters_bundle ON matters(bundle_id)`; `idx_matters_org ON matters(org_id)`.

### 3.25 `matter_values` — live editable canonical values (REQ-030, REQ-031)

**Rationale:** a row-per-value editable store (`UNIQUE (matter_id, canonical_field_id)`)
is the Matter form's live data surface. Determinism comes from the **snapshot columns on
`matters`** (`input_snapshot_json`/`input_snapshot_hash`): a run freezes the snapshot at
execution time, so later edits to `matter_values` never alter a historical run — separate
concerns, one schema.

```sql
CREATE TABLE matter_values (
  id                 TEXT PRIMARY KEY,
  matter_id          TEXT NOT NULL REFERENCES matters(id) ON DELETE CASCADE,
  canonical_field_id TEXT NOT NULL,       -- fields.field_id of the bound version's schema
  value_json         TEXT NOT NULL,       -- typed value (JSON)
  updated_at         TEXT NOT NULL DEFAULT (datetime('now')),
  UNIQUE (matter_id, canonical_field_id)
);
```

Indexes: `idx_matter_values_matter ON matter_values(matter_id)`.

### 3.26 `generation_runs` — append-only run records (REQ-033, REQ-034, ADR-012)

**Rationale:** the unit of reproducibility: matter, exact bundle version, input
snapshot/hash, engine version, requested vs produced documents, warnings, errors,
status. Runs and their outputs are **never mutated** — triggers reject UPDATE/DELETE,
mirroring `generation_log`. A rerun creates a new run (REQ-034).

```sql
CREATE TABLE generation_runs (
  id                  TEXT PRIMARY KEY,
  matter_id           TEXT NOT NULL REFERENCES matters(id) ON DELETE CASCADE,
  bundle_id           TEXT NOT NULL REFERENCES bundles(id),
  bundle_version_id   TEXT NOT NULL REFERENCES bundle_versions(id),  -- exact version used
  input_snapshot_json TEXT NOT NULL,        -- canonicalized matter data at run time
  input_snapshot_hash TEXT NOT NULL CHECK (length(input_snapshot_hash) = 64),
  engine_version      TEXT NOT NULL,        -- docx_engine semver
  status              TEXT NOT NULL DEFAULT 'pending'
                      CHECK (status IN ('pending','running','succeeded','failed','partial')),
  warnings_json       TEXT NOT NULL DEFAULT '[]',
  errors_json         TEXT NOT NULL DEFAULT '[]',
  created_at          TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at        TEXT
);

-- generation_runs is append-only (REQ-033, REQ-034)
CREATE TRIGGER trg_generation_runs_append_only_update
BEFORE UPDATE ON generation_runs
FOR EACH ROW
BEGIN
  SELECT RAISE(ABORT, 'generation_runs is append-only (REQ-033): UPDATE forbidden');
END;

CREATE TRIGGER trg_generation_runs_append_only_delete
BEFORE DELETE ON generation_runs
FOR EACH ROW
BEGIN
  SELECT RAISE(ABORT, 'generation_runs is append-only (REQ-033): DELETE forbidden');
END;
```

Indexes: `idx_generation_runs_matter ON generation_runs(matter_id)`;
`idx_generation_runs_version ON generation_runs(bundle_version_id)`;
`idx_generation_runs_bundle ON generation_runs(bundle_id)`.

### 3.27 `generated_documents` — run output artifacts, never mutated (REQ-034, REQ-035)

**Rationale:** one row per output artifact of a run. `output_path` points at
`<app_data>/docforge/output/<matter_id>/<run_id>/` — **no BLOB (REQ-004)**. Historical
artifacts are never overwritten; a rerun produces new files under a new run directory.
`bundle_document_id` is nullable for ad-hoc exports; SQLite's UNIQUE treats NULL as
distinct, so only bound documents are deduplicated per run.

```sql
CREATE TABLE generated_documents (
  id                 TEXT PRIMARY KEY,
  generation_run_id  TEXT NOT NULL REFERENCES generation_runs(id) ON DELETE CASCADE,
  bundle_document_id TEXT REFERENCES bundle_documents(id),  -- NULL = ad-hoc artifact
  document_name      TEXT NOT NULL,        -- deterministic name from output config
  format             TEXT NOT NULL CHECK (format IN ('docx','pdf')),
  output_path        TEXT NOT NULL,        -- FS path, NO BLOB (REQ-004, ADR-003)
  status             TEXT NOT NULL CHECK (status IN ('generated','skipped','failed')),
  created_at         TEXT NOT NULL DEFAULT (datetime('now')),
  UNIQUE (generation_run_id, bundle_document_id)
);
```

Indexes: `idx_generated_documents_run ON generated_documents(generation_run_id)`.

## 5. Migration v4 → v5 (transactional, one-time)

**Source:** shipped schema v4 (Data Model v2 + template bundles + bug book, see
`src-tauri/src/migrations.rs`, `CURRENT_SCHEMA_VERSION = 4`). Target DB file remains
`<app_data>/docforge/docforge.db`. Run inside one transaction with
`PRAGMA foreign_keys = ON`; all v1/v4 tables are preserved exactly.

1. **Snapshot backup** — copy `docforge.db` (and `-wal`/`-shm` if present) to
   `docforge.db.bak-v4` before any DDL.
2. **Create v5 tables** — run the §3.18–§3.27 DDL (10 new tables + triggers + indexes).
3. **Promote v1 template groups to Bundle Versions.** Each existing `bundles` row becomes
   the v2 Bundle identity (same row, unchanged columns). For each one, in order:
   - insert a `bundle_versions` row:
     `version = 1`, `status = 'draft'`, `created_by = 'user-local'`,
     `note = 'migrated from v1 bundle group'`, and `manifest_json` built as the ordered
     list of member templates (from `bundle_templates.position`) plus an empty output
     config — the v1 grouping is preserved exactly.
   - for each `bundle_templates` row insert a `bundle_documents` row
     (`bundle_version_id`, `template_id`, `position`, `include_default = 1`,
     `condition_ref = NULL`).
   - The existing `bundles`/`bundle_templates` rows are **kept untouched** for rollback;
     fields/mappings/rules start empty and are filled during Phase 2
     (architecture §20.2) — migrated bundles show a `needs_setup` badge.
4. **Templates unchanged** — `templates` / `template_versions` rows, lifecycle states,
   rollback, and standalone fill flows are untouched. Nothing is rewritten (REQ-004,
   REQ-010).
5. **`generation_log` retained** — all existing audit rows remain; no backfill. Going
   forward, v2 run-based generation additionally writes a `generation_log` row (linking
   `run_id` in the services layer) for audit continuity (REQ-013, REQ-033). Inserts are
   unaffected by the append-only triggers (they guard UPDATE/DELETE).
6. **Finalize:** `PRAGMA user_version = 5;`
   `INSERT INTO schema_version (version, applied_at) VALUES (5, datetime('now'));`
   (the shipped v4 ledger exposes only `version` + `applied_at`).
7. **Verify:**
   - `PRAGMA foreign_key_check;` → zero rows.
   - Count parity: for every migrated bundle, `bundle_documents` count equals the v1
     `bundle_templates` count; `bundle_versions` count equals `bundles` count;
     `templates` / `generation_log` counts unchanged.
   - Published-immutability test: publish a version, then attempt
     `UPDATE bundle_versions SET note='x' WHERE id=<published>` and `DELETE` — both must
     `RAISE(ABORT)` via the triggers.
   - `SELECT count(*) FROM generation_log;` equals the pre-migration count.
   - Smoke: existing standalone-template fill still works end-to-end; migrated bundles
     appear on the Bundles screen with `needs_setup`.

## 6. Deliberate Deviations (v5)

| # | Deviation | Rationale |
|---|---|---|
| D1 | `input_snapshot_json` / `input_snapshot_hash` snapshot columns on `matters` (rather than a separate `matter_data` table) | The live, editable store is `matter_values`; the snapshot is the deterministic generation contract. Freezing input at run time means later edits never alter a historical run (REQ-030, REQ-033) |
| D2 | `matter_values` row-per-value store instead of architecture §15's single `matter_data.values_json` document | Row granularity with `UNIQUE (matter_id, canonical_field_id)` gives typed per-field validation, touch-tracking, and diff-able updates while the snapshot columns preserve determinism |
| D3 | `field_mappings` first-class table instead of scattered string replacement | The explicit deterministic mapping layer is data — validated, queried, and surfaced by the Health Check — never ad-hoc replacement logic (REQ-028, ADR-011) |
| D4 | `generation_runs` is append-only (UPDATE/DELETE triggers) | Mirrors the `generation_log` immutability pattern; defense-in-depth for REQ-033/REQ-034: runs and their outputs are never mutated, a rerun is a new run |
| D5 | `matters.org_id` nullable | Local-first personal workspaces instantiate matters without a tenant row (REQ-019); org scoping applies only in Business/Enterprise |
| D6 | `rules.field_id` is plain TEXT, not a DB FK | Draft-time rule authoring may precede field creation; the rule DSL is type-checked against the canonical schema at parse time — the enforcement point is the parser, not the schema (REQ-037) |
| D7 | `bundle_versions.status` uses the full `draft/review/published/archived` lifecycle (architecture §15: `draft/published`) | Reuses the proven template lifecycle semantics (REQ-010) and gives governed orgs a review state before publish; append-only guards apply once `published` |
| D8 | `bundle_documents.template_id` nullable, with `include_default` + `condition_ref` | Supports rule-driven and not-yet-bound documents at draft time; the rules join points live here (REQ-036) |
| D9 | Published-version immutability enforced by triggers (`WHEN OLD.status = 'published'`) | Defense-in-depth in addition to app-layer guards — a published snapshot cannot be edited or deleted through any SQL path (REQ-024) |
| D10 | `generated_documents.bundle_document_id` nullable + `document_name` denormalized | Ad-hoc exports and deterministic output naming are both representable; SQLite UNIQUE treats NULL as distinct, so only bound documents are deduplicated per run (REQ-035) |

## 8. Filesystem Layout Contract

```
<app_data>/docforge/
├── docforge.db                                  # SQLite metadata index (this schema)
├── templates/<template_id>/v<version>/template.docx   # v1/v2 DocumentTemplates, DPAPI-encrypted
│                                                    # (tree unchanged — REQ-004, ADR-003)
├── bundles/<bundle_id>/v<version>/              # bundle assets (draft + published snapshots)
│   ├── documents/<template_id>.docx             # bundle document bytes, DPAPI-encrypted
│   └── manifest.json                            # mirrors bundle_versions.manifest_json
├── licenses/<license_id>/offline-license.lic    # enterprise signed license file
└── output/<matter_id>/<run_id>/                 # generated documents — never mutated
    ├── <document_name>.docx                     # per generated_documents.output_path
    └── <document_name>.pdf
```

`storage_path` / `output_path` values in `templates`, `template_versions`,
`generated_documents` are absolute paths inside this tree; `template_store::resolve(path)`
canonicalizes and verifies containment before any read or write (REQ-018 path-traversal
guard). `bundle_documents` resolve their bytes through `templates.storage_path`; bundle
asset copies under `bundles/<bundle_id>/v<version>/` are written only when a version is
snapshotted, so a published version's files are as immutable as its rows (REQ-024).
