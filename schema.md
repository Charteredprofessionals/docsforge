# DocForge — Data Schema Specification (Data Model v2)

> Owner: Data Engineer | Engine: Authr OS SDLC Studio (Phase 1)
> Status: aligned with `architecture.md` §12 (Data Model v2) and `requirements.md` v1
> Scope: DDL specification only — no application source code. The schema supersedes the
> legacy `src-tauri/src/schema.rs` (BLOB-based prototype schema) via the migration
> strategy in §8. SQLite via `rusqlite` (bundled), WAL mode, metadata-only index.
> Target `PRAGMA user_version = 2`.

---

## 1. Storage Principles

| Principle | Rule | Source |
|---|---|---|
| FS-backed templates, no BLOBs | `templates` and `template_versions` store a filesystem `storage_path` only. Document bytes live under `<app_data>/docforge/templates/<template_id>/v<version>/template.docx`, DPAPI-encrypted at rest on Windows (REQ-019). No BLOB columns anywhere in the index. | REQ-004, AC-004, ADR-003 |
| Integrity hash | Every stored template version keeps a `content_sha256` (hex, 64 chars) computed over the file bytes at save time and re-verified on load, rollback, and export. | REQ-004, REQ-010 |
| Immutable audit | `generation_log` is append-only: application never exposes UPDATE/DELETE, triggers reject them, FK actions default to RESTRICT so referenced rows cannot be deleted out from under the audit. | REQ-013, AC-013 |
| Offline-first | All tables are local; nothing is written unless the user opts in (telemetry/cloud surfaces are zero-knowledge). | REQ-019, REQ-020 |
| SQLite runtime settings | `PRAGMA journal_mode = WAL; PRAGMA foreign_keys = ON; PRAGMA busy_timeout = 5000;` single-writer model per architecture §10. | architecture §10/§12 |

**Identifiers:** every PK is a `TEXT` UUID (v4, generated by the `uuid` crate) unless
noted. **Timestamps:** ISO-8601 UTC `TEXT` via `datetime('now')`. **Booleans:**
`INTEGER` `0|1`. **JSON:** validated `TEXT` documents; the application parses with
`serde_json` and rejects malformed input before write.

## 3. Table Definitions

### 3.1 `orgs` — tenant / plan container

Columns:

| Column | Type | Constraints | Meaning |
|---|---|---|---|
| `id` | TEXT | PK | org UUID |
| `name` | TEXT | NOT NULL | display name |
| `plan` | TEXT | NOT NULL, DEFAULT `'free'`, CHECK `IN ('free','pro','business','enterprise')` | entitlement tier (mirrors `licenses.tier` for the org-level license) |
| `settings_json` | TEXT | NOT NULL, DEFAULT `'{}'` | org policy overlay / non-sensitive settings |
| `created_at` | TEXT | NOT NULL, DEFAULT `datetime('now')` | created timestamp |

Notes: Free/Pro single-user installs seed exactly one implicit personal org
(`org-personal`) at first run — zero-friction local profile (REQ-019, §13 of
architecture). `settings_json` carries org defaults; `policy_config` carries
enforcement-critical policy (see §3.12).

### 3.2 `users` — local identity, RBAC role, SSO mapping

Columns:

| Column | Type | Constraints | Meaning |
|---|---|---|---|
| `id` | TEXT | PK | user UUID |
| `org_id` | TEXT | NOT NULL, FK → `orgs(id)` ON DELETE CASCADE | owning org |
| `name` | TEXT | NOT NULL | display name |
| `email` | TEXT | UNIQUE COLLATE NOCASE (NULL allowed) | login email; NULL until set for local profiles |
| `role` | TEXT | NOT NULL, DEFAULT `'viewer'`, CHECK `IN ('viewer','filler','creator','approver','admin')` | RBAC role (REQ-011) |
| `active` | INTEGER | NOT NULL, DEFAULT `1`, CHECK `IN (0,1)` | soft-disable (admin deactivation) |
| `auth_source` | TEXT | NOT NULL, DEFAULT `'local'`, CHECK `IN ('local','saml')` | identity provider (REQ-021) |
| `external_sub` | TEXT | — | SSO subject (SAML NameID), required for `saml` rows |
| `created_at` | TEXT | NOT NULL, DEFAULT `datetime('now')` | created timestamp |
| `updated_at` | TEXT | NOT NULL, DEFAULT `datetime('now')` | last change timestamp |

Integrity rules:
- `CHECK (auth_source = 'local' OR external_sub IS NOT NULL)` — SAML users must carry a
  verified subject; local users never need one.
- Seat assignment lives on `license_seats.assigned_user_id` (see §3.8); the
  architecture v2 sketch's `users.license_seat_id` is intentionally omitted to avoid a
  circular FK (deviation D3, §9).
- RBAC is enforced in the services layer (`governance::authorize`), never trusted from
  the renderer (REQ-011, AC-011).

### 3.3 `templates` — template index (head of version chain)

Columns:

| Column | Type | Constraints | Meaning |
|---|---|---|---|
| `id` | TEXT | PK | template UUID |
| `org_id` | TEXT | NOT NULL, FK → `orgs(id)` ON DELETE CASCADE | owning org (org-scoping on every query, architecture §10) |
| `name` | TEXT | NOT NULL COLLATE NOCASE, UNIQUE with `org_id` | display name |
| `version` | INTEGER | NOT NULL, DEFAULT `1` | current head version (max of `template_versions.version`) |
| `status` | TEXT | NOT NULL, DEFAULT `'draft'`, CHECK `IN ('draft','review','published','archived')` | lifecycle state (REQ-010) |
| `storage_path` | TEXT | NOT NULL | absolute path to the current version's file — **no BLOB (REQ-004)** |
| `content_sha256` | TEXT | NOT NULL, CHECK `length = 64` | integrity hash of the file at `storage_path` |
| `fields_json` | TEXT | NOT NULL, DEFAULT `'[]'` | typed field schema: JSON array of `{id, label, type, options?, required?}` (REQ-008; types: text/date/dropdown/checkbox/signature) |
| `description` | TEXT | — | free-text description |
| `created_by` | TEXT | NOT NULL, FK → `users(id)` | authoring user |
| `created_at` | TEXT | NOT NULL, DEFAULT `datetime('now')` | created timestamp |
| `updated_at` | TEXT | NOT NULL, DEFAULT `datetime('now')` | last change timestamp |
| `last_published_at` | TEXT | — | timestamp of last successful publish |
| `published_by` | TEXT | FK → `users(id)` | approving user who published |

Notes:
- **REQ-004 / AC-004:** the `templates` table stores `storage_path` only; a saved
  template round-trips through filesystem storage. `content_sha256` gives integrity
  verification on load/rollback/export.
- Lifecycle and allowed transitions are defined in §5 and enforced by
  `trg_templates_status_transition` (DDL §7) plus `governance::transition_status`.

### 3.4 `template_versions` — immutable version history (REQ-010)

Columns:

| Column | Type | Constraints | Meaning |
|---|---|---|---|
| `id` | TEXT | PK | version UUID |
| `template_id` | TEXT | NOT NULL, FK → `templates(id)` ON DELETE CASCADE | owning template |
| `version` | INTEGER | NOT NULL, UNIQUE with `template_id` | 1-based monotonically increasing version number; rollback target |
| `status` | TEXT | NOT NULL, CHECK `IN ('draft','review','published','archived')` | template lifecycle state at the time this version was created (historical snapshot) |
| `storage_path` | TEXT | NOT NULL | filesystem path `<app_data>/docforge/templates/<template_id>/v<version>/template.docx` — **no BLOB (REQ-004)** |
| `content_sha256` | TEXT | NOT NULL, CHECK `length = 64` | integrity hash of this version's file |
| `fields_json` | TEXT | NOT NULL, DEFAULT `'[]'` | field schema snapshot for this version |
| `note` | TEXT | — | human note, e.g. "fix merge field" |
| `created_by` | TEXT | NOT NULL, FK → `users(id)` | author of this version |
| `created_at` | TEXT | NOT NULL, DEFAULT `datetime('now')` | created timestamp |

Integrity rules:
- `UNIQUE (template_id, version)` — the rollback key (REQ-010, AC-010).
- `ON DELETE CASCADE` from `templates`: deleting a template removes its versions, which
  is permitted only when the template has no `generation_log` references (RESTRICT
  protects the audit; §3.5).
- `templates.version` must always equal `MAX(template_versions.version)` for that
  template; maintained transactionally by `TemplateService.create_version`.
- Rollback creates a new head version whose file is restored from the target snapshot
  (architecture §5.4), never mutates history.

### 3.5 `generation_log` — immutable audit trail (REQ-013, AC-013)

Columns:

| Column | Type | Constraints | Meaning |
|---|---|---|---|
| `id` | TEXT | PK | audit entry UUID |
| `org_id` | TEXT | NOT NULL, FK → `orgs(id)` (RESTRICT) | org scope for `docforge audit export --org` and usage reports |
| `template_id` | TEXT | NOT NULL, FK → `templates(id)` (RESTRICT) | template used |
| `template_version` | INTEGER | NOT NULL | exact version filled/exported |
| `fields_hash` | TEXT | NOT NULL | SHA-256 of canonicalized field values (content-free digest, REQ-013) |
| `output_name` | TEXT | NOT NULL | output artifact display name |
| `format` | TEXT | NOT NULL, CHECK `IN ('docx','pdf','html','dfpkg')` | export format (REQ-007) |
| `user_id` | TEXT | NOT NULL, FK → `users(id)` (RESTRICT) | acting user |
| `machine_id` | TEXT | NOT NULL | stable per-install machine UUID (first-run generated, DPAPI-protected) |
| `status` | TEXT | NOT NULL, CHECK `IN ('success','failed','validation_error')` | outcome |
| `error_code` | TEXT | — | structured error code from §8 of architecture (`unclosed_tag`, `invalid_docx`, …) when `status != 'success'` |
| `duration_ms` | INTEGER | NOT NULL, DEFAULT `0` | generation wall-time; feeds aggregate usage reports and telemetry counts |
| `generated_at` | TEXT | NOT NULL, DEFAULT `datetime('now')` | event timestamp |

**Immutability design (REQ-013 / AC-013):**
1. **Append-only API:** the only writer is `governance::record_generation` (architecture
   §3.3); the storage layer exposes `INSERT`/`SELECT` only for this table. No
   UPDATE/DELETE code path exists in the services layer.
2. **Trigger guard:** `trg_generation_log_append_only_update` and
   `trg_generation_log_append_only_delete` (DDL §7) `RAISE(ABORT, …)` on any UPDATE or
   DELETE, defense-in-depth against accidental or malicious modification.
3. **RESTRICT FKs:** `org_id`/`template_id`/`user_id` carry no `ON DELETE` action, so
   referenced templates, users, or orgs with audit history cannot be deleted out from
   under the audit (integrity by construction).
4. **Content-free:** audit entries carry digests and metadata only — never document
   bytes or field values (REQ-019).
5. **Export:** `view_audit_export` (DDL §7) materializes the exportable projection used
   by `export_audit` (REQ-013, REQ-014, AC-013) and `GET /v1/audit?since=` (REQ-016).

### 3.6 `licenses` — license master (REQ-015)

Columns:

| Column | Type | Constraints | Meaning |
|---|---|---|---|
| `id` | TEXT | PK | license UUID |
| `org_id` | TEXT | NOT NULL, FK → `orgs(id)` ON DELETE CASCADE | licensed org |
| `key_hash` | TEXT | UNIQUE (NULL allowed) | SHA-256 of the normalized activation key; plaintext keys are never persisted |
| `tier` | TEXT | NOT NULL, CHECK `IN ('free','pro','business','enterprise')` | entitlement tier |
| `seat_count` | INTEGER | CHECK `> 0` when `tier = 'business'` | size of the per-seat pool |
| `device_limit` | INTEGER | NOT NULL, DEFAULT `0`, CHECK `>= 0` | Pro device cap (`2`), `0` = not applicable |
| `grace_days` | INTEGER | NOT NULL, DEFAULT `30`, CHECK `IN (30,60,90)` | grace window: 30 consumer, 60 company/business, 90 enterprise |
| `status` | TEXT | NOT NULL, DEFAULT `'active'`, CHECK `IN ('active','suspended','revoked','expired')` | lifecycle status; `revoked` recorded via `revoke(device)` |
| `issuance_source` | TEXT | NOT NULL, DEFAULT `'key'`, CHECK `IN ('key','file','cloud')` | how the license entered the system |
| `issued_at` | TEXT | NOT NULL, DEFAULT `datetime('now')` | issuance timestamp |
| `activated_at` | TEXT | — | first successful activation |
| `expires_at` | TEXT | — | subscription/perpetual expiry |
| `revoked_at` | TEXT | — | revocation timestamp |
| `revoked_reason` | TEXT | — | admin-supplied reason |

Integrity rules:
- `CHECK (tier <> 'business' OR (seat_count IS NOT NULL AND seat_count > 0))` —
  Business licenses must define their seat pool.
- `CHECK (tier <> 'pro' OR device_limit > 0)` — Pro licenses must carry the 2-device
  cap.
- `CHECK (issuance_source <> 'key' OR key_hash IS NOT NULL)` — key-issued licenses must
  record the key digest.
- Zero-knowledge: license payloads are activation facts only (REQ-019, ADR-007).

### 3.7 `license_seats` — per-seat pool (Business, REQ-015)

Columns:

| Column | Type | Constraints | Meaning |
|---|---|---|---|
| `id` | TEXT | PK | seat UUID |
| `license_id` | TEXT | NOT NULL, FK → `licenses(id)` ON DELETE CASCADE | pool owner |
| `seat_number` | INTEGER | NOT NULL, CHECK `> 0`, UNIQUE with `license_id` | seat index `1..seat_count` |
| `assigned_user_id` | TEXT | FK → `users(id)` ON DELETE SET NULL | currently assigned user; NULL = free seat |
| `assigned_at` | TEXT | — | assignment timestamp |
| `status` | TEXT | NOT NULL, DEFAULT `'available'`, CHECK `IN ('available','assigned','suspended')` | seat state |

Integrity rules:
- `UNIQUE (license_id, seat_number)` — one row per pool seat; the application creates
  `seat_count` rows at activation (REQ-015 per-seat pools, REQ-014 admin seat UI).
- Assignment is tracked here rather than on `users` to avoid a circular FK (deviation
  D3, §9); the admin console reads/writes this table (REQ-014).

### 3.8 `devices` — offline device activations (REQ-015, AC-015)

Columns:

| Column | Type | Constraints | Meaning |
|---|---|---|---|
| `id` | TEXT | PK | activation UUID |
| `license_id` | TEXT | NOT NULL, FK → `licenses(id)` ON DELETE CASCADE | license being activated |
| `machine_id` | TEXT | NOT NULL, UNIQUE with `license_id` | stable per-install machine UUID |
| `machine_fingerprint` | TEXT | NOT NULL | salted SHA-256 of the hardware fingerprint (tamper-resistant binding) |
| `activated_at` | TEXT | NOT NULL, DEFAULT `datetime('now')` | activation timestamp |
| `last_seen_at` | TEXT | — | last successful entitlement check |
| `status` | TEXT | NOT NULL, DEFAULT `'active'`, CHECK `IN ('active','revoked','deactivated')` | activation state |
| `revoked_at` | TEXT | — | revocation/deactivation timestamp |

Integrity rules:
- `UNIQUE (license_id, machine_id)` — one activation row per machine per license;
  re-activation after deactivation reuses the row (status flip), so device counts stay
  accurate.
- **Device-limit enforcement** (`licensing::evaluate_entitlement`): for `tier = 'pro'`,
  `COUNT(*) WHERE status = 'active'` per license must be `< license.device_limit`
  (2 devices, REQ-015 / AC-015). Enforcement is application logic; the schema provides
  the counting basis.
- Offline activation writes the row locally with no phone-home; optional later sync to
  the license server carries activation facts only (REQ-015, REQ-019).

## 5. Template Lifecycle (REQ-010, REQ-012)

States: `draft → review → published → archived`, plus unarchive/reject edges.

| From | Allowed to | Actor | Notes |
|---|---|---|---|
| `draft` | `review`, `archived` | creator | submit for approval / retire |
| `review` | `published`, `draft` | approver/admin (publish); creator or approver (reject back) | approver cannot bypass review (AC-011/AC-012) |
| `published` | `archived` | approver/admin | only published versions are fillable by `viewer`/`filler` (REQ-012) |
| `archived` | `draft` | admin | unarchive reopens editing |

- Enforced by `trg_templates_status_transition` (DDL §7) and, authoritatively, by
  `governance::transition_status` (architecture §3.3, §5.4).
- Each transition that creates or promotes a file version writes a new
  `template_versions` row and advances `templates.version` (rollback target, REQ-010).
- Publishing stamps `templates.last_published_at` / `templates.published_by`.

## 6. Audit Immutability (REQ-013, AC-013)

The audit contract: **append-only, tamper-evident, exportable, content-free.**

1. **Append-only API** — `governance::record_generation` is the sole writer; INSERT
   only. No UPDATE/DELETE is ever issued for `generation_log` by any layer.
2. **Trigger guard** — UPDATE/DELETE triggers `RAISE(ABORT)` (DDL §7); any bypass
   attempt fails closed at the SQLite layer.
3. **RESTRICT FKs** — `orgs`, `templates`, `users` referenced by `generation_log` cannot
   be deleted while audit rows exist; the audit outlives its subjects.
4. **Export** — `view_audit_export` returns metadata + digests only (no bytes/values),
   consumed by `export_audit` (GUI, REQ-013), `docforge audit export` (REQ-016), and
   `GET /v1/audit?since=` (REQ-016). Export is a `SELECT`, preserving immutability.
5. **Aggregation** — usage reports read aggregates only (`COUNT`, `SUM(duration_ms)`,
   `GROUP BY org_id, generated_at`), never content (REQ-014).

## 7. DDL (SQLite-compatible)

```sql
-- DocForge Data Model v2 — target PRAGMA user_version = 2
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;

-- 3.13 migration ledger
CREATE TABLE schema_version (
  version     INTEGER PRIMARY KEY,
  description TEXT NOT NULL,
  applied_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 3.1 tenant / plan container
CREATE TABLE orgs (
  id            TEXT PRIMARY KEY,
  name          TEXT NOT NULL,
  plan          TEXT NOT NULL DEFAULT 'free'
                CHECK (plan IN ('free','pro','business','enterprise')),
  settings_json TEXT NOT NULL DEFAULT '{}',
  created_at    TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 3.2 local identity + RBAC + SSO mapping
CREATE TABLE users (
  id           TEXT PRIMARY KEY,
  org_id       TEXT NOT NULL REFERENCES orgs(id) ON DELETE CASCADE,
  name         TEXT NOT NULL,
  email        TEXT UNIQUE COLLATE NOCASE,
  role         TEXT NOT NULL DEFAULT 'viewer'
               CHECK (role IN ('viewer','filler','creator','approver','admin')),
  active       INTEGER NOT NULL DEFAULT 1 CHECK (active IN (0,1)),
  auth_source  TEXT NOT NULL DEFAULT 'local'
               CHECK (auth_source IN ('local','saml')),
  external_sub TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  CHECK (auth_source = 'local' OR external_sub IS NOT NULL)
);

-- 3.3 template index (head of version chain) — storage_path, NO BLOB (REQ-004)
CREATE TABLE templates (
  id                TEXT PRIMARY KEY,
  org_id            TEXT NOT NULL REFERENCES orgs(id) ON DELETE CASCADE,

-- §5 lifecycle enforcement (REQ-010, REQ-012)
CREATE TRIGGER trg_templates_status_transition
BEFORE UPDATE OF status ON templates
FOR EACH ROW
WHEN NEW.status <> OLD.status
BEGIN
  SELECT RAISE(ABORT, 'invalid template status transition (REQ-010/REQ-012)')
  WHERE NOT (
    (OLD.status = 'draft'     AND NEW.status IN ('review','archived')) OR
    (OLD.status = 'review'    AND NEW.status IN ('published','draft')) OR
    (OLD.status = 'published' AND NEW.status IN ('archived')) OR
    (OLD.status = 'archived'  AND NEW.status IN ('draft'))
  );
END;

-- §6 audit immutability (REQ-013)
CREATE TRIGGER trg_generation_log_append_only_update
BEFORE UPDATE ON generation_log
FOR EACH ROW
BEGIN
  SELECT RAISE(ABORT, 'generation_log is append-only (REQ-013): UPDATE forbidden');
END;

CREATE TRIGGER trg_generation_log_append_only_delete
BEFORE DELETE ON generation_log
FOR EACH ROW
BEGIN
  SELECT RAISE(ABORT, 'generation_log is append-only (REQ-013): DELETE forbidden');
END;

-- §6 exportable, content-free audit projection (REQ-013, REQ-014, REQ-016)
CREATE VIEW view_audit_export AS
SELECT
  g.id,
  g.generated_at,
  g.org_id,
  g.template_id,
  t.name                AS template_name,
  g.template_version,
  g.user_id,
  u.name                AS user_name,
  u.email               AS user_email,
  g.machine_id,
  g.format,
  g.status,
  g.error_code,
  g.duration_ms,
  g.fields_hash,
  g.output_name
FROM generation_log g
LEFT JOIN templates t ON t.id = g.template_id
LEFT JOIN users u    ON u.id = g.user_id;
```

## 8. Migration & Seed Strategy (legacy → Data Model v2)

**Legacy source** (`src-tauri/src/schema.rs`): `templates` with `original_docx` /
`template_docx` BLOB columns; `generation_log` with `(id, template_id, output_name,
format, generated_at)`. Target DB file remains `<app_data>/docforge/docforge.db`
(architecture §12: BLOBs and the Base64 bridge are deleted — ADR-003, ADR-004).

Steps (one-time, transactional, `PRAGMA foreign_keys = OFF` during the cutover):

1. **Backup & rename legacy tables**
   `ALTER TABLE templates RENAME TO legacy_templates;`
   `ALTER TABLE generation_log RENAME TO legacy_generation_log;`
   Kept for one release to enable rollback; dropped thereafter.
2. **Create v2 schema** — run the §7 DDL. Insert `schema_version(1, 'legacy schema')`.
3. **Seed identity (zero-friction consumer, REQ-019):**
   - `orgs('org-personal', 'My Workspace', 'free', '{}')`
   - `users('user-local', 'org-personal', 'Local User', NULL, 'admin', 1, 'local', NULL)`
   - `licenses('lic-free-1', 'org-personal', NULL, 'free', NULL, 0, 30, 'active', 'key', …)`
4. **Migrate templates (BLOB → FS, REQ-004):**
   For each `legacy_templates` row, in one transaction:
   - mkdir `<app_data>/docforge/templates/<id>/v1/`; write `template_docx` bytes to
     `template.docx` (DPAPI-encrypt per REQ-019).
   - `content_sha256` = SHA-256 of the written file bytes.
   - `status` = `'published'` — legacy templates were directly fillable; publishing
     preserves REQ-012 behavior for existing library items.
   - Insert `templates` row (`created_by` = `'user-local'`) and
     `template_versions` v1 row (`status` = `'published'`, same `content_sha256`,
     same `fields_json`).
   - `original_docx` is **dropped**, per ADR-003 (the untagged original is not
     reconstructible and is out of scope).
5. **Migrate audit history:** copy each `legacy_generation_log` row into
   `generation_log` with: `org_id` = `'org-personal'`, `template_version` = `1`,
   `user_id` = `'user-local'`, `machine_id` = `'migrated-legacy'`,
   `fields_hash` = SHA-256 of the migrated template's canonical `fields_json`
   (documented approximation: the legacy schema never recorded value hashes; all new
   entries hash canonicalized field values), `error_code` = NULL, `duration_ms` = `0`.
   Original `id`/`generated_at` are preserved for traceability. Inserts are unaffected
   by the append-only triggers (they guard UPDATE/DELETE).
6. **Finalize:** `PRAGMA user_version = 2;`
   `INSERT INTO schema_version(2, 'data model v2 (FS-backed, no BLOB)');`
7. **Verify:** `PRAGMA foreign_key_check;` count parity per table; sample
   file round-trip + `content_sha256` recompute; confirm
   `SELECT count(*) FROM generation_log;` equals legacy count.

## 9. Deliberate Deviations from the architecture v2 Sketch (§12)

| # | Deviation | Rationale |
|---|---|---|
| D1 | `content_sha256` added to `templates` and `template_versions` | Integrity verification for FS-backed documents (REQ-004/REQ-010) |
| D2 | `generation_log.org_id`, `error_code`, `duration_ms` added | Org-scoped audit export (REQ-014/REQ-016), structured error traceability (§8), aggregate reports (REQ-014/REQ-020) |
| D3 | `users.license_seat_id` dropped; assignment lives on `license_seats.assigned_user_id` | Avoids the circular FK between `users` and `license_seats`; single authoritative seat link |
| D4 | New tables `license_seats`, `license_files` | Explicit per-seat pools and enterprise offline license files (REQ-015) |
| D5 | `users.email` made nullable (UNIQUE when present) | Zero-friction offline consumer profile (REQ-019) |
| D6 | `licenses.key_hash` (digest) replaces plaintext key storage | Secrets hygiene (architecture §7: secrets never in config) |
| D7 | Triggers + `view_audit_export` added | Defense-in-depth audit immutability and export contract (REQ-013) |
| D8 | `policy_config` scoped `global/user/org/device` with `source_path`, `content_sha256` | Precise enterprise policy-file deploy semantics (REQ-021) |
| D9 | `schema_version` ledger | Versioned migrations per architecture §12 |

## 11. Filesystem Layout Contract

```
<app_data>/docforge/
├── docforge.db                        # SQLite metadata index (this schema)
└── templates/<template_id>/v<version>/template.docx   # versioned, DPAPI-encrypted
└── licenses/<license_id>/offline-license.lic          # enterprise signed license file
```

`storage_path` values in `templates` / `template_versions` are absolute paths inside
this tree; `template_store::resolve(storage_path)` verifies containment before any read
(REQ-018 path-traversal guard).
